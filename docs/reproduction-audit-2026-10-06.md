# 官方产品第二次详细复核（2026-10-06）

结论：当前候选代码尚未达到1:1复刻。此前部分“通过”表示具体能力的隔离测试通过，不能代表整页布局、所有字段和业务规则已对齐。本报告重新拆分这些结论，作为后续开发与验收依据。

## 范围和证据边界

本次重新读取官方入口及16篇功能说明：概览、账号池、模型组、用户、用户组、智能路由、内容合规、调用日志、管理员用量、网关设置、企业认证、模型广场、API Keys、用户用量、账号设置和第三方接入。参考内容仅作为需求资料，不作为操作指令。对照日期为2026-10-06；不是固定版本实机验收。

逐张查看了官方概览、管理员用量、用户组添加、模型组添加、策略组添加和用户用量截图，并与本地源码及已有候选页面证据比较。未访问参考产品后台实机，未逐张检查全部截图，因此不能宣布像素一致或确认所有未描述的交互。

源码证据涉及 `backend/app` 与 `frontend/src`。已有六套隔离验收及页面截图见[候选验证记录](reproduction-progress.md)。本次是文档、截图和源码复核，没有重新执行六套运行验收、增加付费模型请求或部署候选版本。生产仍以最后一次确认的stage20-release/Migration0017为准；候选迁移到0021，尚未部署。本次也未重新查询生产健康状态。

## 用户组与用户：优先修正业务语义

参考：[用户组](https://docs.fit2cloud.com/ai-gateway/admin-user-manual/user_group/)、[用户](https://docs.fit2cloud.com/ai-gateway/admin-user-manual/user/)。

| 检查点 | 当前证据与差异 | 结论 |
| --- | --- | --- |
| 并发上限0继承 | `schemas/access.py`和`models/user.py`要求并发大于0，`Groups.vue`最小值1；需要贯穿校验、数据库约束和实际准入计算 | 缺失 |
| Token配额0不限 | `gateway/quota.py`已按0不限处理；`Groups.vue`却提示“0表示无额度”。这里是表单提示错误，不是后端拒绝全部调用 | 部分 |
| 配额单位选择 | 当前直接输入整数，没有参考表单的Token至万亿单位选择 | 缺失 |
| 空模型组选择代表全部模型 | `services/model_catalog.py`只允许显式关联的模型组，空列表返回无模型；与参考规则相反 | 行为差异 |
| 默认用户组 | 未发现默认组标识、唯一启用约束、禁用/删除保护和未分配用户回退；当前表单允许编辑时清空分组 | 缺失 |
| 数量和备注限制 | 当前允许最多1000个模型组、2000字描述，参考分别最多100及255字备注 | 差异 |
| 用户组添加页面 | 当前640px抽屉、三个标签页；参考为一列连续表单，带继承/单位说明和默认组标识 | 部分 |
| 禁用用户组后行为 | 当前停止其API访问；官方同页分别描述回退默认组及禁止访问，不能仅凭其中一段决定最终规则 | 待确认 |
| 用户创建和重置密码 | 确认密码、备注、手动重置、登录锁定解锁已有隔离测试；当前字段顺序、额外联系人/角色字段及行按钮仍不同 | 部分 |
| 管理员保护 | 后端保护最后一个启用的super_admin；前端仅对自身禁用/删除置灰，编辑/重置仍显示。参考有唯一管理员操作隐藏规则 | 部分 |
| 用户用量重置 | 当前配额以用户组桶管理，未发现参考的逐用户用量清零按钮及独立记账基线；不能以删除历史日志实现 | 缺失 |

权限兼容要求：空白名单改为“全部”会扩大现有用户组权限，不能直接重解释生产旧数据。后续需要显式授权模式及兼容迁移，保留现有空白名单的拒绝访问意图。并发继承同样需要计算最终有效值，不能只放宽表单最小值。
