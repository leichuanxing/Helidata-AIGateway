# 负载均衡与供应商联动检查

检查日期：2026-10-18。保持现有架构、授权、配额、限流和内容合规流程，未新增数据库迁移。

## 发现并修复的问题

| 优先级 | 问题 | 修复 |
| --- | --- | --- |
| 高 | 供应商修改协议后，目录仍可能展示无可用协议的统一模型；监控仍可能显示节点健康 | 统一按当前模型类型和供应商实际协议判断可用性；无兼容节点时目录隐藏统一模型，监控明确显示不兼容 |
| 高 | 供应商或映射修改后，节点保留旧健康/冷却状态，旧请求完成时也可能覆盖新配置的健康状态 | 修改连接或映射后重置关联节点健康状态；健康回写锁定并核对路由和供应商配置版本 |
| 中 | 健康检查使用账号默认协议，独立协议地址可能检查错位置 | 按节点模型类型选取可用操作，再选对应协议和服务地址 |
| 中 | 删除供应商或映射后，保留失效节点的路由无法保存或停用 | 允许保留原有失效节点并修改组状态；失效节点不可调度，新增时仍拒绝已删除映射 |
| 中 | 运行监控快速切换路由组时，旧请求可能覆盖新路由面板 | 按路由 ID、时间范围和请求代次隔离返回值，关闭或切换面板时作废旧请求 |
| 低 | 新增路由仍展示“推理”类型 | 同步已完成的选项移除，既有配置仍兼容 |

## 已验证范围

- 路由组新增、编辑、删除、别名冲突、配置版本冲突、分组授权引用保护。
- 轮询、加权轮询、最少并发、随机、优先级；节点启停、路由和供应商共享并发额度及资源释放。
- 超时与限流切换、未知处理结果默认不重试、SSE 异常后不重放、冷却探测和后台恢复。
- Chat、Responses、Messages 的普通及 SSE 请求，多模态图片透传、向量、重排序和图片生成协议。
- 供应商停用/启用、映射停用、类型变化、协议不兼容、上游模型更名、映射删除、供应商删除。
- 不同协议独立地址下的健康检查；节点状态、模型目录、实际转发行为一致。
- 普通用户授权、底层物理模型隔离、撤销授权、内容合规阻断及调用日志追踪。
- 前端类型检查与生产构建。

自动化测试使用隔离容器，实际经过 Nginx、FastAPI、SQLAlchemy、PostgreSQL、Redis、HTTPX 和本地可控上游。未以商业供应商响应替代协议测试，也未发起生产付费模型请求。

最终版本后端 **115 项全部通过**（58.334 秒），前端 **26 项全部通过**，Vue/TypeScript 类型检查和 Vite 构建通过。未跳过已启用的 PostgreSQL、Redis 和 HTTP 集成测试。

## 使用边界与部署方案

- 模型列表检查验证连接及鉴权，不能证明图像生成或其他推理任务一定可执行；不支持模型列表的上游仍需单独验证生成能力。
- 上游已处理后的超时或断连可能计费，网关无法保证外部服务恰好执行一次；保持不确定结果重试默认关闭。
- 未进行长时间压力测试或全部商业供应商实测。
- 部署前完整备份数据库、配置、主密钥及数据目录，保留旧容器。继续使用原数据目录和 18080 端口；检查健康和页面，失败恢复原数据和容器。不推送 GitHub。
