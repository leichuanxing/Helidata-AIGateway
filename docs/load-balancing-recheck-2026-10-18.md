## 发现并修复的问题

| 级别 | 问题 | 修复及证据 |
| --- | --- | --- |
| 高 | 普通模型组切换到后继模型时，只有智能路由分支重新执行目标模型合规，普通后继模型可能绕过其专属策略 | 所有目标逻辑模型变化均检查对应策略；真实 HTTP 中两个原模型节点鉴权失败后，后继模型命中敏感词返回 403，后继上游调用数为 0 |
| 高 | 连接未建立的失败仍保留未知预算，有限配额下可能无法继续切换 | 为每次尝试记录明确未处理状态；仅这类失败释放预算，读超时等不确定结果仍保守结算；真实 PostgreSQL 验证预算释放、下一次重置与不确定预算保留 |
| 中 | 本地 HTTP 连接池已耗尽、尚未发出请求，也被记为未知预算 | JSON 与 SSE 两条路径标记未发送；保留不自动重试本地池耗尽的行为，避免资源压力放大 |
| 中 | 重试排队期间达到请求总期限，会改写上一个节点的失败原因并重复累计健康故障 | 总超时仅对正在调用的节点记一次故障；排队超时保留此前连接错误；两种情况均有独立调度边界回归测试 |
| 中 | 节点监控尚未加载或加载失败时保存，会把现有权重清空 | 加载期间阻止保存；加载失败时保留已保存权重；只有成功获取节点列表后才清理不再关联的权重 |
| 低 | 一个供应商映射多个模型，删除第一个模型后，仍关联的节点权重行可能消失 | 先按当前组成员筛选，再按供应商去重；新增前端测试覆盖 |
