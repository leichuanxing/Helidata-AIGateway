# 模型组负载均衡

基于 v1.0.8，在现有模型组、供应商、模型映射、Redis 并发租约和调用日志上扩展。数据库迁移版本为 `0032`，无需新增供应商或复制模型。

## 配置入口

在“模型组 → 编辑”中配置：

| 参数 | 说明 |
| --- | --- |
| 调度策略 | 轮询、加权轮询、最少并发；历史组保留原有粘性调度，新建组默认最少并发 |
| 节点权重 | 每个供应商在当前组中的权重，1–100，默认 1；加权轮询采用平滑加权算法 |
| 最大重试次数 | 0–7，不含首次；一次请求最多发送 8 次，不重复尝试同一映射 |
| 单次尝试超时 | 1–3600 秒，默认 120 秒；普通响应及 SSE 建连生效，总耗时仍受系统非流式超时约束 |
| 允许结果不确定时重试 | 默认关闭；开启后允许读取超时、上游异常及无效响应后的重试，存在重复计费风险 |

供应商的**优先级、最大并发、启停状态**继续在现有供应商配置维护。模型组中可打开对应供应商；负载监控中可直接启停账号，操作会明确提示其对所有引用组生效。映射启停继续复用供应商内模型映射开关。

节点权重按供应商账号设置，同一账号在组内的多个映射共用该权重。修改模型组成员时，界面会移除不再属于当前组的权重。新建供应商映射自动成为对应逻辑模型的候选节点，未配置权重时使用 1。

## 调度顺序

1. 复用原有模型授权、API Key 限流、内容合规及智能路由决策。
2. 保留请求模型及模型组后继模型的顺序，不随机改变业务模型。
3. 优先采用上游实际支持的原生协议，再按供应商优先级分层，数值越小越优先。
4. 对同一模型、协议层级和优先级的可用节点执行所选算法；容量耗尽或不可用时才进入下一层。
5. 最少并发比较供应商实时占用请求数；轮询/加权轮询不受旧粘性缓存干预。历史粘性策略继续保留其既有排序。

智能路由明确使用决策选中的目标模型组策略。普通模型请求没有携带模型组 ID：同一逻辑模型属于多个已授权组时，确定性地采用 ID 最小的组；没有模型组但具备“全部模型”授权的模型沿用原有调度。若需要不同业务使用不同策略，应使用独立逻辑模型名称或明确的智能路由目标组。

## 并发与健康

算法选择与全局、用户组、API Key、供应商四级名额预留在同一个 Redis Lua 事务中完成。仅准入成功才推进轮询权重计数；队列等待不改变分配比例。节点容量以供应商账号为单位共享，避免多个模型或模型组同时使用同一账号时突破上游限制。

复用既有租约过期、续租和取消清理机制。故障达到阈值后进入冷却，冷却到期最多允许一个探测请求，成功清除故障状态并恢复容量。鉴权失败账号摘除后，可由现有定期健康检查或账号连接检查恢复；定期检查频率沿用系统设置，关闭定期检查时不会自动执行后台探测。

## 故障切换与计费边界

- 明确的连接建立失败/超时、鉴权拒绝和限流可以在剩余次数内切换。
- 参数错误、权限错误、配额错误、内容合规阻断和客户端断开不触发上游故障切换。
- 所有后继逻辑模型均重新检查其专属内容合规策略，包括普通模型组；明确未建立连接和本地连接池耗尽时释放预留预算，处理结果不确定时仍保守保留预算。
- 读超时、写失败、上游 5xx、响应损坏不能证明上游没有生成或计费，默认停止重试。管理员可显式开启不确定结果重试。
- SSE 响应交给客户端后，无论是否已收到有效文本，都不重放请求；流中断使用原有 SSE 错误与终态日志。
- 故障切换仍重新检查映射有效性和 Provider 配置版本；智能路由切换后继模型继续执行对应模型的内容合规检查。

通用 HTTP API 无法保证跨供应商“恰好一次计费”。默认策略减少自动重复请求的风险，不能承诺上游一定不计费。`X-Request-ID` 用于追踪，不等于供应商幂等键。

## 监控与日志

“模型组 → 负载监控”提供最近 1 小时、24 小时、7 天的节点请求数、成功率、平均响应时间、实时并发、优先级、权重、健康状态、冷却截止时间与最近错误。

实时并发包含供应商在其他模型组中的占用；请求统计按当前组成员逻辑模型与供应商汇总，所以共享逻辑模型的跨组调用也包含在内。数据来自真实调用日志尝试记录，包含失败节点，客户端取消计入请求数。历史没有耗时的记录不纳入统计；无样本显示“—”，不是 0%。平均时间是完整上游尝试时长，SSE 为完整流时长，不是 TTFT。历史保留范围受调用日志保留策略约束。

调用详情的原有请求链路增加调度策略、模型组 ID、实际映射 ID、节点权重/优先级/最大并发快照、重试次数、切换原因，以及不确定结果重试被抑制的原因。

## 上线与回退

本次开发不改变生产配置，不自动推送 GitHub。上线前应备份数据库、配置文件和 Provider 加密主密钥，保留原镜像和原数据挂载。先在数据副本上执行 `alembic upgrade head` 并检查健康，再安排容器替换窗口。

迁移只新增配置列和约束，原有模型、映射、授权和日志保留。降级到 `0031` 会删除本次新增的负载均衡配置，回升后恢复为默认值；因此生产回退应优先保留新数据库、使用备份恢复方案评估兼容性，不能将降级当作无损操作。
