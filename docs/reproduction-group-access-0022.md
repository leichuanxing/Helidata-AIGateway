# 用户组差异修正与0022迁移

日期：2026-10-06。执行用户“发现差异直接修改、提交代码、重新构建应用”的要求，本轮修改用户组实际规则和对应页面，接续内部demo v1.3.0复刻。

## 实现

- 组并发与Key并发允许0；有效组并发不超过网关上限，Key不超过有效组上限。准入的Redis原子计数使用最终限制，概览和详情返回有效值。
- 新组空模型选择默认为全部模型；目录、网关模型鉴权、未分组模型调度及模型组查询入口使用同一授权规则。虚拟路由仍检查目标组存在且启用。
- 增加显式`model_access`，旧组迁移为`selected`；旧空授权组继续拒绝访问，旧客户端未传模式的编辑也保留此规则。前端对旧空授权显示兼容提示，可由管理员明确改为全部授权。
- 创建唯一系统默认组。默认组不能通过API禁用/删除，数据库限制默认组必须启用且至多一条；新用户未选组时归入默认组，无组用户在鉴权和目录查询时解析默认组。禁用组继续拒绝访问，避免按文档冲突描述扩大权限。
- 旧库有Provider时，新默认组保持无模型授权，防止旧无组用户意外获得访问权限；没有Provider的全新库默认组开放全部模型。旧组并发值和模型关联保持原样。
- 用户组页面按实机连续表单及列表列序调整，加入并发继承提示、Token单位、模型标签、状态开关、默认标识与保护。新用户表单默认选择默认组。
- 新建备注限制255字、模型组最多100个；历史超限值可原样保留。既有配额周期不重解释，编辑时保留周期入口。
- Key和模型组保存增加重复提交保护。

## 兼容及回退

迁移不清除历史、不重设配额、不修改旧用户归属或旧组权限。`0022`降级要求先显式消除全部授权及0继承配置，否则拒绝降级；需要回退应用时应使用迁移前完整备份恢复，而不是强制缩改权限字段。

当前尚未解决整个v1.3.0的Jev、MFA、开放API、代理、共享向量、企业认证、ES和完整统计等缺口。默认组禁用后的回退规则也不用于旧已禁用组，维持拒绝访问。保留兼容功能的额外字段意味着仍不能称为完整1:1。

## 验证

新增`tests/reproduction_group_access.py`：在独立数据库schema真正执行0021结构到0022迁移，检查默认名称冲突、旧限制和拒绝范围保留；检查API默认组保护、新用户默认归属、旧请求授权兼容、负数422及普通用户403；验证目录/鉴权/调度对未分组模型的授权，以及实际Redis达到继承上限后拒绝超量请求；验证无组API Key解析默认组并获得正确模型组范围。
