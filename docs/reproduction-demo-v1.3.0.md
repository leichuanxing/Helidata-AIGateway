## 实机与文档冲突及新增能力

- 账号新建抽屉实际提示“大数值优先”，与公开文档“小数值优先”冲突。本轮未提交请求测算法，提示不能证明实际派发顺序；当前候选小数值优先调度不在本轮翻转。
- 账号并发允许0且提示不额外限制；当前候选需要正数，须与用户组继承一起设计。
- 账号类型多了独立重排序；账号可选网关代理，网关基础页存在统一上游代理配置。
- 路由新增Jev模式、决策提供商、2至10个目标及兜底组；统计增加Jev调用/回退/Token。新建样本没有单样本阈值输入，默认勾选保存生成向量；当前候选的覆盖阈值及默认不构建是不同流程，不能沿用旧文档结论宣布一致。
- 系统设置新增基础/开放API/企业认证三标签，包含会话空闲控制和MFA。企业认证卡片并不能替代身份绑定、MFA和开放API。
- 用户新建提示密码6至128字节，而当前项目要求至少12位和复杂度；本轮不降低现有密码策略。严格复刻若需变更，应将安全策略显式建模并保留旧账号兼容。
- 实机虚拟模型默认`auto`，消除了仅靠不同截图猜测默认名称的问题；可配置别名仍需实际保存与派发测试。

## 本轮项目实现与限制

已将模型组页面调整为参考列序及模型标签，抽屉改为440px顶部标签，按名称→协议类型→模型→备注排列，保留真实API保存、自定义模型、排序与引用保护。旧禁用组保留状态恢复入口，避免布局修改造成旧数据无法维护。列选择与排序尚未实现，因此该页仍为部分对齐。

API Keys使用440px创建/编辑抽屉、名称校验、行开关与请求期间禁用、前4后4脱敏、参考列序；一次性明文及后端摘要存储不变。模型广场新增独立重排序分类；用户组0配额提示修正为不限。所有操作连接现有后端，不新增演示数据到生产。

本轮不会把尚未实现的Jev、MFA、企业认证或ES绘制成可保存但不生效的表单。应按上述清单逐项扩展持久化/API/引擎，再接页面。整个v1.3.0复刻仍未完成。
