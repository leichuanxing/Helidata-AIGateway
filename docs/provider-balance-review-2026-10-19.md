# 模型供应商与负载均衡路由复查

## 范围与问题清单

基于 v1.0.8 当前代码，复用已有供应商、模型映射、独立负载均衡路由、Redis 租约及调用日志实现，不新增重复模块，不调整数据库结构。

| 优先级 | 问题 | 处理 |
| --- | --- | --- |
| P2 | 节点探测仅确认模型列表接口可连接，节点模型未出现在列表中仍标为健康 | 核对上游模型名称，返回 `TEST_MODEL_NOT_FOUND` 及 `model_available=false`，不再错误清除故障状态 |
| P2 | 后台/手动健康探测一次临时失败就摘除节点，未遵循连续失败阈值 | 累计失败达到路由阈值后冷却；鉴权失败/限流继续立即冷却；成功恢复并清零 |
| P3 | Redis 状态不可用时节点并发数据显示空白 | 显示 `—`，避免与零并发混淆 |
| P3 | 节点手动检查的成功提示仅说连接正常 | 明确已找到上游模型、没有执行生成，并说明不完整模型列表的限制 |

## 验证范围

- 供应商：预设/套餐保存与读取、发现模型、连接检查、默认模型、映射增删改、Key 更换与保留、启停、删除、同名重建、版本冲突及权限边界。
- 负载均衡：路由增删改、统一名称冲突和授权关联保护、节点启停、五种策略、节点/供应商/路由并发上限、配置持久化。
- 联动：供应商停用/删除、映射停用/删除/类型变化/上游名称变化、协议或地址修改后的节点状态重置、目录可见性。
- 请求：Chat Completions、Responses、Anthropic Messages 的 JSON/SSE，多模态、向量、重排、生图；现有 13 个供应商/操作适配组合。
- 异常：超时、限流、上游异常、不确定结果禁止重试、SSE 开始后不切换、冷却恢复、并发释放、调用日志及统计、目标模型内容合规。
- 新增回归：模型列表未找到节点模型；三次连续临时失败才冷却；成功恢复后失败计数及冷却清零。

## 测试边界

自动化接口测试在独立临时容器中运行，使用真实 FastAPI、Nginx、SQLAlchemy、PostgreSQL、Redis、HTTPX；上游是可控本地 HTTP 服务，不将其描述为商业供应商付费实测。生产验收仅检查页面、健康和现有配置，不修改业务账号或创建测试路由。

模型列表不支持、分页或未包含可调用模型时，列表检查不能证明生成能力。应使用具备预算授权的实际请求确认；本轮不发起商业计费请求。自建实例仍须实际部署对应类型与协议的模型。

## 部署方案

数据库版本保持 0033。部署前备份数据库、完整持久化目录和容器配置，保留原容器；保持 `/opt/AIGateway/data` 和 18080 端口。替换后检查四个 Supervisor 进程、健康接口和页面，失败恢复原数据和容器。不推送 GitHub。
