2026-10-05（Asia/Shanghai）部署应用0.10.0、镜像helidata-ai-gateway:stage10，数据库仍为Migration0006，无新增表。访问 http://192.168.31.97:18080。Chat/SSE调用方法沿用stage-8.md和stage-9.md，本阶段替代其中调度未开放及不切换账号的历史说明。

## 账号选择与会话

候选必须来自实时启用的用户组授权、模型组成员、逻辑映射和账号；排除禁用、删除、Unavailable和未到期Cooling账号，仅选择当前Chat接口支持的OpenAI兼容协议。每次账号占用后再核对配置版本、启用状态和映射权限，避免配置更新期间使用已过时的候选。

同一逻辑模型内优先使用仍可用且未满并发的Sticky账号；其他账号按优先级降序、负载比例、活跃请求数、连续失败数和id排序。Sticky不越过当前逻辑模型优先级链：请求模型仍可用时先处理请求模型，后继模型只在其账号不可用/失败/满载时使用。

Redis键为sticky:{apikey_id}:{client_ip_hash}:{requested_model}，使用数据库Key id而非API Key明文；IP用SHA256摘要前24位，来自ASGI识别的客户端地址，不自行信任客户端声明。值为成功账号id，TTL1800秒；仅实际成功后建立/刷新，流式需上游DONE且完成终态处理。禁用、删除、冷却或满并发的原账号会被跳过，成功的新账号替换粘性关系。粘性存储失败不绕过容量校验。

## 账号容量

Redis provider:{id}:concurrency 用有期限的所有权令牌统计Active Requests，不是QPS。Lua原子清理过期令牌、比较max_concurrency并占用名额，避免先读再加的竞态。拒绝占用时继续其他候选；同优先级按实际负载排序。

占用持续到非流式结果完成，或SSE真正结束/取消/失败；失败后先清理本次连接和名额，再切换账号。所有权90秒，每20秒续租，长SSE不会只因为运行较久而释放占用。Redis服务端时钟用于过期判定；进程崩溃遗留占用可过期回收。无法获取调度状态时返回503 SCHEDULER_UNAVAILABLE；无法续租会取消请求并记失败，不伪装为客户主动断开。Redis故障时清理尝试失败则由期限回收。

账号级上限已实际执行；Gateway/User Group/API Key的限制、排队和配额仍为阶段11。预检读取候选状态，不占账号名额、不调用上游、不建立Sticky或改变账号健康。

## 故障转移

可恢复的上游HTTP/鉴权/限流/网络/超时/协议格式失败，在响应开始前尝试同逻辑模型的其他账号。已尝试的映射不重复发送，每请求最多访问8个候选；非流式调用和流式响应头获取共用120秒调度总期限，不是每账号重新获得120秒。

同模型账号全部不可用或失败后，按模型组保存顺序尝试后继逻辑模型。只访问当前用户组已授权且包含原请求模型的启用组；不回绕前面的成员，不访问任意其他组。后继成员必须与请求模型具有相同模型类型，以保护多模态等能力边界。每次重查权限，撤销授权/成员后不能继续访问。传给上游的是后继映射真实名称，响应仍使用调用者请求的逻辑名称。

上游400/422属于请求参数错误，直接返回400，不切账号、不计为账号故障。客户端断开不会切换或增加账号失败数。SSE一旦上游成功响应头已交给流式响应，就不重试；即使第一事件格式异常，也发送脱敏event:error并结束。已有内容绝不追加另一账号生成的回答。

重发POST不能保证上游计费或执行恰好一次：网络失败可能发生在上游已经开始处理之后。该边界由最多8候选/120秒总期限、相同映射不重复、参数错误不切换和SSE响应开始后不重试限制。没有跨请求去重或计费退款承诺。

## 健康状态

管理员账号列表/详情返回并展示scheduling_state和current_concurrency；容量无法读取时显示不可读取，避免伪造0。原有health_status保留用于连接检查。

| 调度状态 | 行为 |
| --- | --- |
| Available / 可用 | 启用且不处于冷却/硬故障；未测试账号也可以接受真实请求 |
| Cooling / 冷却中 | 冷却尚未结束，不接新请求 |
| Unavailable / 不可用 | 鉴权硬故障或显式连接测试失败，需修正配置/测试恢复 |
| Disabled / 已禁用 | 禁用或删除，不参与调度 |

普通瞬时失败首次只记录失败，连续第2次起进入30、60、120、300秒冷却，之后上限300秒。429首次立即冷却30秒，重复429按60、120、300秒退避。冷却到期账号成为可探测候选，原子占用限制为1；恢复探测实际调用成功后重置失败数/冷却并标记healthy，失败继续退避。恢复按真实请求触发，不启动后台付费生成探测。

401/403即时标记unhealthy/Unavailable。管理员修改配置会按既有逻辑重置状态；显式连接测试成功会清除冷却并恢复healthy，但模型列表检查不等同于生成能力验证。健康更新通过独立短事务及行锁序列化，并核对config_version，旧请求结果不能覆盖已修改账号。取消和非上游错误不污染健康。

Request ID贯穿各次尝试，脱敏运行日志列出失败账号id/错误代码和最终结果，不记录模型真实名称、URL、Key或请求正文。完整业务日志页面/表为阶段12。
