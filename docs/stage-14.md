# 阶段14：管理员 Dashboard

2026-10-05（Asia/Shanghai）。应用0.14.0，镜像helidata-ai-gateway:stage14，数据库迁移继续为0010。本阶段没有数据库结构变更，沿用阶段13小时/日统计表。访问 http://192.168.31.97:18080/admin/dashboard。管理员登录后默认进入此页；普通用户继续进入模型广场。

## 指标与窗口

页面提供最近1小时、24小时、7天、30天四个用量窗口，默认24小时。活跃用户、失败/取消及排行榜按所选时段；今日请求与今日已上报Token独立从北京时间00:00至当前统计时间。输入/输出/缓存/总Token、请求/成功/失败趋势复用阶段13统计服务，未上报值保持未知，不估算。今日Usage缺失数量明确展示。

实时执行请求、其中流式请求、队列长度来自Redis实际租约。网关显示当前/配置最大并发，达到80%时提示接近上限；Provider和用户组显示实际当前/配置上限。实时状态和数据库统计分别标注时间，两者不是同一时刻快照。

新增gateway:streaming有序集合；只有实际获准执行的stream=true Chat请求加入，排队者不计入。写入与原四级准入同一Lua脚本；沿用90秒TTL/20秒续租并在资源关闭时移除，覆盖响应头前/流中错误、成功、断开和重新准入。流式计数是执行中声明为流式的请求，包括等待上游响应头的阶段。清除到期及不再拥有网关租约的条目，避免崩溃残留变成虚假活跃数。

## 并发历史

FastAPI生命周期内独立任务每10秒从真实Redis状态采样，以Redis时间对齐分钟；分钟记录执行/流式/队列的已观测峰值及样本数，保留31天，数据随Redis持久化目录保留。1小时视图按分钟展示，24小时按小时、7/30天按天展示已采样峰值。未知桶返回NULL而非0，ECharts不跨空缺连接。采样开始前没有历史，不从日志反推或制造旧并发；离散采样可能遗漏短于10秒的峰值，不等于时段内精确最大值。实际验收产生的负载采样保留为运行历史，不混入持久化测试用户或Token事实。

Redis不可读时仍返回数据库统计，实时全局/流式/队列、Provider和用户组负载均NULL，页面显示“不可用”；历史读取异常有独立状态。采样异常只写通用告警并继续重试，不输出密钥、URL或请求内容，也不改变推理结果。

## 汇总与排行

GET /api/admin/dashboard?period=1h|24h|7d|30d，仅admin/super_admin可读，未登录401、普通用户403、未完成首次改密仍受原门禁。返回selected summary、today、series、live、concurrency_series、rankings、providers、groups及时间元数据。

统计与排行使用共享source_query：完整日/小时读取usage_daily/usage_hourly，精确边界只读取最多两段各不超过一小时的索引日志。SQL重复读事务使所选/今日统计、排行及对象查询使用同一数据库快照；不执行一次全时间范围的call_logs扫描。

Provider/模型按已上报总Token排名，最多Top10加“其他”，包含请求数、失败数和Token有效样本。Provider维度保留未选择和已删除对象，不伪造当前名称；模型按最终逻辑模型优先、否则请求模型归并，避免一个请求重复计入模型排行。无usage的维度不能解释为消耗为0。后台资源表最多显示100个对象，并显示总数和完整管理页入口，避免超大表拖慢首页。

## 页面联动

- 失败指标卡片和失败趋势数据点跳转调用日志，带status=failed、operation=chat和对应精确时间范围。
- Token趋势数据点跳转用量统计；其他请求趋势点跳转对应时段日志。1/24小时图表按小时、7/30天按天。
- Provider状态名称、可定位的Provider排行榜数据点进入账号详情；已删除账号和“其他”不提供错误的详情入口。
- 用户组名称进入该组筛选的用量统计；模型排行榜进入对应模型统计。右上角可进入完整用量页。
- 页面支持手动刷新和可关闭的15秒自动刷新；后台标签页暂停轮询，离开页面清理定时器和ECharts实例。请求失败时显示错误并移除旧指标，避免把旧快照当成当前状态。
