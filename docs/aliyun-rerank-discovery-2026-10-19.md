# 阿里云重排序账号模型发现修复

## 原因

选择重排序后使用 DashScope 原生 `/api/v1` 地址。发现模型仍沿用 OpenAI `data[].id` 解析，无法识别原生 `output.models[].model`，因此原生格式响应被判为无效。

依据：[阿里云查询模型列表接口](https://help.aliyun.com/zh/model-studio/list-models)。原生接口包含 `output.total` 和 `page_no` / `page_size` 分页参数。

## 修复

- 阿里云原生基础地址使用专用列表解析，逐页获取模型 ID。
- 保留原有 OpenAI 兼容列表格式，也兼容返回 OpenAI 格式的私有代理。
- 始终沿用配置的域名、代理及鉴权，不把 Key 发送到其他地址。
- 限制整体列表请求时间、分页数、总条数和响应大小；异常和不前进的分页明确失败，不悄悄截断列表。
- 发现模型、连接检查和负载均衡节点探测共用适配器，因此一并修复。
- 不修改业务账号、Key、映射和数据库结构；不发起生成请求，不推送 GitHub。

## 验证边界

使用真实本地 HTTP 服务验证原生分页、鉴权头、格式错误、不前进分页、超量列表、兼容列表，以及管理后台 `/api/admin/providers/discover-models` 接口。不是商业供应商生成调用，也不表示已经验证所有地域 Key 的权限。

## 结果
后端 117 项测试全部通过，无跳过。包含原生分页 HTTP 适配测试和管理后台发现接口回归。前端无代码修改，沿用上一轮已经验证的生产静态资源。
